# Python 类

## 类的构造过程

1. 读取类体形成 code object 并执行
2. 将类中的属性（数据描述符）、方法（非数据描述符）封装到一个命名空间字典中
3. 通过元类（type）构造出类对象
```python
CLSObj = type(name, (bases,), namedspace_dict)
```

## 类的实例化
1. `type.call` 为总控方法
2. `type.__new__ ` 申请内存空间并将其返回，自动触发 `__init__` 方法为实例进行初始化（一般认为在这里生成实例字典： `__dict__`）

## 相关说明
类中定义的类属性、实例方法等存储在类字典中。**方法逻辑共享，属性状态私有（实例属性）**
在使用 `self.method` 时，经历了以下六步查找法：
1. 数据描述符。在类中定义了 `__get__` & `__set__` 方法的数据
2. 实例字典 `__dict__`。存放实例属性，通常在调用实例方法 `___init__` 时生成
3. 非数据描述符（仅定义了 `__get__` 方法的类）。类中定义的实例方法通常在这个步骤找。
    - 在调用实例方法时（`self.method`）会将 `function object` 转化为 `bound method`（不需要手动传 self 参数）
4. 类字典 `__dict__`。存放类属性
5. `__MRO__` 继承链重复上述步骤
6. `__getattr__`



# Python 类与对象底层原理深度笔记

## 一、 类的构造过程 (Class Construction)
> 目标：将“代码字符串”转化为内存中的“类对象（模具）”。

1. **准备命名空间 (__prepare__)**：
   - 元类（默认为 `type`）调用 `__prepare__`，返回一个空的 `dict` 作为临时命名空间。
2. **执行类体代码 (Execution)**：
   - 编译器将类体编译为 `code object`。
   - 在上一步的 `dict` 中执行这些代码：定义函数存入 `function object`，定义变量存入键值对。
3. **铸造类对象 (Type/Metaclass)**：
   - 调用 `type(name, bases, namespace_dict)`。
   - 此时真正的 **类对象 (Class Object)** 在内存中诞生。
   - 临时命名空间转化为 `mappingproxy`（即 `Class.__dict__`），它是只读的，存储共享的逻辑（方法）和类属性。

---

## 二、 类的实例化 (Instantiation)
> 目标：利用“模具”产生“实例对象（零件）”。

1. **总控阶段 (type.__call__)**：
   - 当执行 `obj = MyClass()` 时，触发元类的 `__call__` 方法，它编排了后续的 `__new__` 和 `__init__`。
2. **分配内存 (__new__)**：
   - **角色**：造物主。
   - 调用 `MyClass.__new__(cls)`。在 C 层面分配一块内存空间，并返回一个“毛坯”实例。
   - **注意**：此时实例已诞生，但在现代 Python 中，其实例字典 `__dict__` 可能是延迟生成的（直到第一次赋值）。
3. **装修阶段 (__init__)**：
   - **角色**：装修工。
   - Python 将上步返回的实例作为 `self` 传给 `__init__(self, ...)`。
   - 在此处进行属性赋值（如 `self.task_id = "..."`），这些数据存放在实例自有的 `__dict__` 中。

---

## 三、 属性查找顺序 (The 6-Step Lookup Rule)
> 当执行 `obj.attr` 时，遵循以下优先级：

1. **数据描述符 (Data Descriptor)**：
   - 在类或父类中定义，且同时实现了 `__get__` 和 `__set__`（如 `@property`）。
2. **实例字典 (Instance `__dict__`)**：
   - 存放在实例对象内存中的普通属性（私有状态）。
3. **非数据描述符 (Non-Data Descriptor)**：
   - 在类中定义，且仅实现了 `__get__`。
   - **关键**：类中定义的 **实例方法** 属于此类。此时会触发描述符协议，将 `function` 转化为绑定了 `self` 的 `bound method`。
4. **普通类属性 (Class Attributes)**：
   - 存在于 `Class.__dict__` 中的静态变量或常量。
   - **MRO 继承链**：如果当前类找不到，则顺着 `__mro__` 列表在父类中重复步骤 1、3、4。
5. **兜底方法 (__getattr__)**：
   - 如果上述路径全部失败，且类中定义了 `__getattr__`，则触发此方法进行最后的补救。

## 四、 核心机制总结

### 1. Self 的本质
- `self` 并非关键字，而是实例对象的代号。
- **自动传参原理**：依靠描述符协议。访问 `obj.method` 时，底层执行了 `method.__get__(obj, Class)`，返回一个预先填入了 `obj` 参数的函数包装器。

### 2. Super() 的逻辑
- **非单纯父类**：它是 MRO 链的导航仪。
- **剪枝行为**：它会跳过实例字典和当前类，直接从 MRO 链中当前类的“下一站”开始应用查找逻辑。
- **意义**：确保多继承环境下，所有基类的 `__init__` 被且仅被有序执行一次。

### 3. 性能与内存优化 (__slots__)
- **原理**：在类中定义 `__slots__ = ('attr1', 'attr2')`。
- **后果**：直接关掉该实例的 `__dict__` 生成。
- **Tier 3 场景收益**：
  - 属性从字典查找变为数组偏移查找（更快）。
  - 极大压减海量小对象（如扫描结果）的内存占用，防止 Jenkins Agent OOM。

---

## 五、 架构师寄语
> **“方法逻辑共享（类字典），属性状态私有（实例字典）。”**
> 在设计 Tier 3 业务逻辑（Python Core）时，请务必区分哪些是通用的 Scanner 逻辑，哪些是特定 Job 的 Context 数据。善用 `super()` 进行逻辑解耦，善用 `__slots__` 保护系统内存。
